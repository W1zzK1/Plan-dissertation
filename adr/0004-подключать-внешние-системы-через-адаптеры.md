# 0004. Подключать внешние системы через адаптеры

## Статус

Принято.

## Контекст

MVP зависит от утвержденного расписания, уведомлений и расчета условий перевозки. Реальные API внешних систем могут быть недоступны или меняться.

## Решение

Все внешние системы подключаются через внутренние порты и адаптеры. Доменная логика работает с внутренними интерфейсами, а конкретные HTTP/API-клиенты находятся на инфраструктурной границе. Внешние ПВЗ, постаматы и курьерские службы не входят в MVP и могут быть добавлены позже через тот же подход.

Для прототипа допускаются fake-адаптеры с теми же контрактами.

## Альтернативы

| Альтернатива | Причина отказа |
|---|---|
| Вызывать внешние API прямо из domain service | Доменная логика станет зависеть от партнерских деталей |
| Ждать реальные API до начала проектирования | Затормозит MVP и курсовую |
| Делать отдельный сервис на каждую интеграцию | Избыточно для первой версии |

## Последствия

- Прототип можно развивать до появления реальных API.
- Контрактные тесты фиксируют ожидания к партнерам.
- Нужно поддерживать соответствие fake-адаптеров будущим реальным контрактам.

## Когда пересмотреть

Решение не отменяется при развитии, но отдельные адаптеры можно выделить в сервисы, если они станут сложными или будут использоваться несколькими продуктами.
